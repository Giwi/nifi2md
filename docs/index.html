Apache NiFi → Markdown + Mermaid

nifi2md

Parses an Apache NiFi flow definition JSON file and generates Markdown documentation, one file per process group, each with a Mermaid diagram, all cross-linked from a main index.md. Processors are annotated with the Enterprise Integration Patterns vocabulary, so the pages describe what role each processor plays, not only which class it is.

Features#

Everything the generator emits, in one pass over the flow file.

  • One index.md entry point: flow summary, process group index, parameter contexts and controller services.
  • One file per process group under process-groups/, with breadcrumb links back to the main document and up to the parent group.
  • Mermaid flowchart per group, node shapes encoding the mapped EIP pattern.
  • Processor tables with type, mapped pattern, schedule and full property tables.
  • Connections, input/output ports, child groups, remote process groups, funnels and canvas labels documented per group.
  • Sensitive values (properties and parameters) masked as ********, long values truncated.

Build#

Requires JDK 17+ and Gradle (no wrapper checked in; use a local Gradle 8.x).

gradle build          # compiles, runs tests, builds build/libs/nifi2md-<version>-all.jar
gradle fatJar         # just the executable uber-jar
gradle run --args="path/to/ACME.json"

Usage#

java -jar build/libs/nifi2md-0.1.0-all.jar test/ACME.json

Default output: a <input name>-docs/ directory next to the input file.

test/ACME-docs/
├── index.md                      # summary, parameter contexts, services, group index
└── process-groups/
    ├── acme.md                   # root group: diagram + processors + connections
    ├── acme-service-1.md
    └── ...

Generated documentation#

Files cross-reference each other with relative links, so the output works on a documentation site, in a Markdown viewer, or on GitHub as-is.

index.md

Flow summary (counts of groups, processors, connections, ports, services), process group index tree, parameter contexts with masked sensitive values, controller services with configuration.

process-groups/<group>.md

Breadcrumb links, mermaid flowchart, processor table with mapped integration pattern, connections, ports, child group links, services, remote groups, funnels and canvas labels.

Diagram conventions#

NodeMeaning
([ name ]) stadiumEndpoint processor, or process group port
{ name } rhombusMessage router
{{ name }} hexagonSplitter / aggregator / recipient list
[/ name /] trapezoidMessage translator
( name ) roundProcessor without a mapped pattern
[[ name ]] subroutineNested process group (opens its own page)

Connections pointing at a port of a child group are drawn against that child group node, so each level stays readable.

Sample#

test/ACME.json is a real flow definition (7 process groups, 21 processors, 40 connections). Generated output lives in test/ACME-docs/, and the generated Mermaid diagrams were rendered with @mermaid-js/mermaid-cli to confirm they are valid.

Generated documentation is written next to the input file and is safe to commit: sensitive values are masked and property values are truncated.
